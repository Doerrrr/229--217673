# 双视图发布协议

这是019 v02的新增文件发布协议；变异观测含义与支持域由exchange.md规定。无序输入、REF前缀协调和多倍体语义不变。exchange.md末尾的stdout写出故障和并发排除项只适用于旧stdout调用；本文件明确规定的新文件发布、I/O失败及并发义务优先适用于--out-dir调用，两种模式不要混用。

## 命令

旧stdout调用仍支持；增加文件发布调用：

```bash
cohort-release --manifest batches.tsv --samples B,A --out-dir store --expect NONE
```

expect必填，值为NONE或64位小写SHA-256版本标识。NONE表示当前尚无已提交版本，否则表示调用者预期的旧版本。成功退出0、stdout为空；不使用stdout传送发布产物。

## 版本标识与文件

令input为对象：sources按清单顺序，每项为source和该来源文件原始字节的sha256；samples为请求样本列表，保持请求顺序。版本标识是input对象以UTF-8、JSON键排序、无额外空白（分隔符逗号/冒号）序列化后所得SHA-256。对象中的路径不参与标识；源顺序、内容、source标识和样本顺序参与。输入在一次调用期间不被外部修改。

store/CURRENT是普通文件，内容恰为版本标识加一个LF；无已提交版本时不存在该文件。
三份完整普通文件位于store/generations/版本标识/：

- release.jsonl：原有发布字典下的聚合报告，一位置一行。
- original.jsonl：每条源物理记录一行，按清单来源顺序、原ordinal升序排列；含source、ordinal、chrom、position、reference、alternate、format、samples。reference/alternate仍是原来源字典，不做后缀补齐；format含实际字段。samples只含该源实际具有的请求样本，按请求顺序，每项为name和values。数值和缺失表达遵循原协议，GT含义由该行原字典解释。完整缺失不代表缺席，内容相同的重复记录保留。
- manifest.json：含generation、input、files；files的键恰为release.jsonl和original.jsonl，每项含sha256（产物实际原始字节摘要）和rows（JSON Lines行数）。额外元数据允许。

release/original的JSON键序与空白自由，发布ALT顺序自由；两份视图必须各自正确且对应完全相同的来源记录及观测。原始视图不是从发布字典猜回的残缺记录，也不能把补齐后的参考冒充原参考。

## 提交、读者与冲突

CURRENT可见时对应的三文件必须完整且摘要正确。已提交版本内三文件不可变，后续发布不得修改或删除它们。测试最多六次发布；可保留历史版本，本题不要求垃圾回收。

读者读取CURRENT一次后固定该版本，之后即使CURRENT变更，也继续读固定版本。读者不要求两次分别读取CURRENT仍相同。允许并行准备多个不同版本；提交必须重新判定expect，最多一个基于同一旧版本的不同新版本能成功，另一个退出7。不能只在调用起始检查expect。已经存在且内容相同的版本可复用，但不得修改其字节。

## 正常失败

退出2：CLI/清单结构错误；3：来源不可读或标题不可解析；4：源记录无法解析或参考跨度不兼容；5：请求样本在全部标题中缺席；6：产物/临时文件写入或提交I/O失败；7：expect不等于提交时的当前版本。

上述失败必须有简短stderr、stdout为空、不得崩溃。若有旧版本，CURRENT及所有已提交产物保持原字节。错误只触及未提交暂存内容；后续正常调用仍能成功。测试单独提供一种错误，不要求定义同时多个独立错误时的分类优先级。

本版新增覆盖目录拒绝写入及正常系统调用返回的写出失败。被外部SIGKILL终止的那次命令不用返回正常错误码，但之后不得把未提交版本当成已提交，重试须可完成。无整机断电、网络文件系统或物理磁盘持久性测试；不声称恢复操作系统之外的故障。

## 可控准备门

可选--gate DIR，用于接收端复核。DIR由调用方预先创建。新版本三文件已完整、CURRENT尚未提交时，在DIR/ready写入完整JSON对象，包含generation和stage="PREPARED"，随后等DIR/go存在再尝试提交。等待时不能持有排斥其他准备者的长时间独占锁；两个不同版本应能各自进入PREPARED。没有gate时正常立即继续。ready写出必须完整，不能先让读者看见空/半写对象。

测试利用gate检查旧读者、新提交、提交时冲突和准备后中止，不要求任意时间点猜测进程进度。不允许无条件提前退出来假装处理受控故障。

资源以完整候选命令的Linux wait4 ru_maxrss计量，上限196608 KiB（192 MiB）。计量包括候选启动器和其等待的子进程，由Linux返回该指标；不是同时运行进程RSS的求和，不把私有评分器或数据生成器的RSS计入候选。禁止脱离候选命令、留在后台处理或输出数据；命令结束时其工作进程也须结束。

临时盘允许，不指定内部存储布局，也不以未实现的临时盘计量作为扣分条件。每条命令180秒的保护仅用于结束挂起进程，正常资源检查不以更短时限加难。

公开的大输入范围：单来源40万及80万无序位置、1个样本、4倍体、含REF的5等位、完整GT/AD/PL及DP/GQ/PS；另有16个来源、每源2条同位置记录、每源64样本、4倍体及含REF的17等位宽位点。两种规模均需生成完整、语义正确的两份视图。

40万和80万长来源分别在全新输出目录执行，令其峰值为R400和R800（KiB），要求两者均不超过196608，且 R800 <= 1.25 * R400 + 16384。这一带固定余量的判据考察存储增长形状，而非依赖某个数据量恰好触顶。输入值和来源名可以变化；不得按测试名称、行数或固定数据硬编码答案。
