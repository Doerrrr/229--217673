# DDI-031 verifier 诊断修订

基于个人发布提交 `f8d5fd70cc16ddb6b66e5ded1f6db725c448f733`。原题与冻结原件保留，此版只增加私有判分进度与逐次落盘。Agent7200、Verifier1800、单次候选300秒、2CPU/2048MiB及52项权重不变。

## 记录内容

verifier输出中的每条进度以 `DDI031_DIAG` 开头。记录实例ID、分组、调用序号、候选开始／结束、退出码、超时、实测耗时、图检查开始／结束及耗时、逐项判定、保存开始和结束。每30秒输出心跳，显示当前阶段及已耗时长；不输出见证图或隐藏答案。

每次verifier尝试创建独立目录：

`/logs/verifier/ddi031/diagnostics/<attempt>/`

- `progress.jsonl`：实时追加、flush与fsync的事件。
- `last_state.json`：原子更新的最后阶段。
- `calls/0001.json` 等：每次候选调用完成后立即保存测量摘要。
- `calls/*.stdout.tail.txt` 与 `*.stderr.tail.txt`：只保存有限长度的尾部，避免复制巨大输出。

原有完整 `result.json`、`runtime/` 和reward生成规则不变。诊断不会把未完成的trial写成0分、部分分或成功；日志写入错误不改变计分逻辑。候选UID10001不可读取root祖先目录下的诊断资料。

## 如何解释

- `candidate_begin` 后长期无 `candidate_end`：候选调用／测量环节尚未返回。
- `candidate_end` 后出现 `graph_check_begin` 但无结束：停留在该实例的图校验。
- 多次调用正常结束且总耗时持续增长：调查累计预算。
- `save_begin` 后无 `verifier_complete`：调查最终结果保存。
- 出现超时、信号终止或测量异常时，沿用原无有效分数政策。

## 平台限制

文件落盘和输出刷新不能保证平台界面展示或保留日志。本地Harbor0.5.0源码在测试脚本返回后下载verifier目录；外层超时可能阻止下载。当前平台的挂载、归档和查看机制未确认；没有导出／日志查看能力时，本版仍不能保证用户取回T1现场。进度不会发送到外部服务，也不通过reward字段夹带诊断信息。

此版不能补回旧trial `trial_3dabccc8d6ab4f809ffc557d` 的历史记录，也没有修复或延长累计判分预算。是否改变预算应依据新证据和平台上限另行决定，不能把增加日志当作超时已修复。

验证范围为作者控制：新旧有限见证、NOP逐项结果对照，以及强制终止前的持久化和UID隔离。均不属于新外部模型答卷或T1成绩。

`apply.sh` 只在干净的031平台main上暂存诊断相关文件，校验固定基线、保护工作流／CSV／题面／时限；不会commit、push或触发模型检测。
