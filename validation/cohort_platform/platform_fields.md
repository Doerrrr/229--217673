# DDI-018 v02 平台介绍字段

## Prompt

本题围绕多测序批次的观测发布维护展开。候选需要调查并修复一个可构建的原生 C 工程，使其按既有命令和接收协议聚合 VCF、BGZF VCF 与 BCF。不同来源拥有各自的样本顺序、FORMAT 字段与等位字典，发布结果必须正确保留样本身份、等位与基因型含义、来源优先级和逐条观测追溯。在同一位点存在重复记录、多倍体及宽位点时，不能仅复制来源的数值下标，也不能丢弃未获基因型判定的测量。题目同时要求大输入正常完成且符合公开的峰值内存预算。正确性按公开的实验室政策与消费者协议判定，接受语义等价的字典排序，不要求猜测作者算法或字节布局。

## 环境思路

采用 Python 3.11.17 的 Debian bookworm 容器，预装 gcc、make 及实际使用的压缩库构建依赖。固定 bcftools/HTSlib 1.20 源码在镜像构建阶段完成编译，候选工程位于 /work/cohort-release，公开政策、消费者和样例位于 /packet。平台适配版使用可构建但尚未实现可信报告的迁移草稿；候选可以重写本工程，不允许修改输入或消费者掩盖问题。task.toml 声明 schema 1.3 并启用联网，避免影响平台模型调用链路。

## 测试思路

沿用冻结版本的 33 项业务检查与五类权重，覆盖等位/基因型投影、来源优先级、分组与追溯、有限大输入资源、合法空数据及异常输入完成行为。检查根据来源观测含义核对输出，接受等价 ALT 顺序和 JSON 表达，不比较作者内部布局。原生程序以普通用户执行，私有测试和日志保持不可读写；Linux wait4 记录候选完整命令的 ru_maxrss，192 MiB 上限仅计算候选进程。超时、信号退出、环境错误单独标为运行异常，不当作有效低分。平台版初始草稿与 Oracle 分别验证，旧版外部成绩不转移为新版 T1 证据。

## 参考解思路

使用用户批准的第三份外部原生答卷作为隐藏参考实现基础，在不改变公开协议或评分规则的前提下，修复宽位点时各来源保留的大文本缓冲与解码缓冲。参考实现保持源记录所有权、按统一位点键聚合、以命名样本选择优先观测，并把 GT、AD、PL 投影到发布等位字典，保留缺失含义、相位和来源记录。完成或释放来源时及时释放不再使用的解码资源，避免峰值内存随全部来源缓冲叠加。Oracle 脚本只安装参考修改的源码并使用候选环境现有 Makefile 构建，不把参考实现或私有检查放入候选镜像。
